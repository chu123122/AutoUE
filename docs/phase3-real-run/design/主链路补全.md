# 主链路敌人生成补全计划

## Summary

把当前主链路从“`scripted_smoke` 只能生成 freeze trap”补到“`autoue.py run` 能用确定性敌人 profile 跑完整 1-10 节点，生成目标敌人，stage 到 AIDev，tsc，并进入 PIE 验证攻击相位日志”。保留 `scripted_smoke` 原语义，继续作为 freeze-trap 冒烟用例，不把它改成敌人。

主链路与方案 B 是两条互补路径，共用节点 6-10 确定性 codegen、`stage_generated_ts_to_aidev.py`、`run_autoue_pie_validation.py`：

- 主链路（本计划，`run_enemy_mainchain_pie.py`）：走完整 `autoue.py run`，验证节点 1-5 选择质量、`EncounterSpecPlanner` 消费 manifest、真实 encounter 生成。
- 方案 B（`regen_enemy_pie.py`）：绕开节点 1-5，直接喂 fixture spec 做模板热迭代，不需要 manifest。

## 当前断点

- 断点 1：`scripted_smoke` 在 `core/llm_factory.py` 中固定返回 freeze trap、freeze vfx、空 encounters。后续确定性节点再正确，也只能渲染冰陷阱或空敌人。
- 断点 2：`UEApiMCPFeasibilitySearcher` 的 fixture 路径只认类名 `ScriptedSmokeChatModel`。新增敌人 scripted model 后，如果不改成模型属性开关，会误走真实 MCP 查询，破坏主链路确定性。
- 断点 3：`EncounterSpecPlanner` 需要 `scene_spawn_manifest`。没有 fixture 或真机导出 manifest 时会 fail loud；不能用空 encounter 冒充成功。
- 断点 4：当前 PIE validator 只证明 `enemy_count > 0` 和 adapter 存在，不能证明前摇、active、resolve、死亡、格挡等敌人战斗逻辑真的执行。
- 断点 5：如果 AIDev 地图没有 `AUTOUE_ENEMY_SPAWN_POINT`，生成/部署/tsc 全通过也会在 PIE 里刷不出敌人。

## Key Changes

- 新增确定性敌人 LLM provider：
  - 增加 `scripted_enemy` provider 和 profiles：`scripted_enemy_zombie`、`scripted_enemy_archer`、`scripted_enemy_kamikaze`、`scripted_enemy_shield`。
  - 只固定节点 1-5 输出：split、EAB 选择、thin flow、encounter spec、UE API adjudication；节点 6-10 继续走现有 deterministic Python/codegen 路径，不写死 TypeScript/codegen 输出。
  - 各节点输出要点：
    - `SceneAndGameplaySplitter`：一句房间 + 敌人遭遇的 scene/gameplay 描述。
    - `EntityAbilityBehaviorPlanner`：输出该 case 的 `selected_entity_ids`、`capability_ids`、`behavior_ids`。
    - `ThinGameplayFlowPlanner`：按 behavior 的 actions 产 stages + engine_ports，复用 `tools/generate_dead_cells_enemy_runtime_cases.py` 的 `thin_flow_for` / `PORTS` 形态。
    - `EncounterSpecPlanner`：必须 emit 非空 encounters，`trigger.type=on_level_start`，`spawn_group` 从 manifest 选，`composition` 对应所选敌人；空 encounter 会让下游 `enemy_runtime` 缺席。
    - `UEApiMCPFeasibilitySearcher`：走 fixture evidence，敌人相关 engine_ports 全部判 hit。

- 抽共享敌人 case 定义，作为主链路、方案 B、fixture 的单一来源：
  - zombie → `melee_hitbox`。
  - archer → `projectile_spawn`。
  - kamikaze → `self_destruct`。
  - shield → `directional_block + melee_hitbox`。
  - 复用 `tools/generate_dead_cells_enemy_runtime_cases.py` 中现有 `MELEE / PROJECTILE / SELF / SHIELD` 能力组合，避免三处复制后漂移。

- 补强主链路一键 runner：
  - 新增 `tools/run_enemy_mainchain_pie.py`。
  - 用法：

    ```powershell
    python tools/run_enemy_mainchain_pie.py --case zombie --pie
    python tools/run_enemy_mainchain_pie.py --case archer --pie
    python tools/run_enemy_mainchain_pie.py --case kamikaze --pie
    python tools/run_enemy_mainchain_pie.py --case shield --pie
    python tools/run_enemy_mainchain_pie.py --case all --pie
    ```

  - runner 创建临时 `input/001.txt`，调用：

    ```powershell
    python autoue.py run --input-dir <tmp-input> --output-dir <tmp-output> --llm-profile scripted_enemy_<case>
    ```

  - 生成后检查目标 entity、非空 encounter、`support.status=supported`、生成的敌人 TS 模块、`AutoUEEnemyPresentationRuntime.ts`、stage report、AIDev adapter/uasset/GameMode 绑定。

- 补强 PIE 日志 gate：
  - 扩展 `tools/unreal/validate_autoue_runtime_log.py`：新增 `--require-attack-phase`、`--enemy-case zombie|archer|kamikaze|shield`、`--require-encounter-complete`。
  - 新增解析：`EnemyAttackTelegraph`、`EnemyAttackActive`、`EnemyAttackResolved type=... hit=...`、`EnemyDirectionalBlock`、`EnemyBlocked`、`EncounterCompleted=1`。
  - runner 启 PIE 前记录 AIDev log 大小/时间戳，PIE 后只验证本次新增日志切片，避免旧日志假通过。

## 最小修复顺序

1. 抽共享 enemy case 定义，例如放到 `core/scripted_enemy_cases.py`，从现有 fixture generator 迁移四类 case 的 entity、behavior、capability、attack type、prompt 文案、期望日志。
2. 在 `core/llm_factory.py` 增加 `ScriptedEnemyChatModel(case)`，并让 `create_llm()` 支持 `provider == "scripted_enemy"`。
3. 在 `config/llm-profiles.example.json` 增加四个 `scripted_enemy_*` profile；profile 只声明 case，不写死 codegen/template 输出。
4. 把 `UEApiMCPFeasibilitySearcher._use_fixture()` 从类名判断改成 `getattr(node.model, "use_mcp_fixture", False)`；`ScriptedSmokeChatModel` 和 `ScriptedEnemyChatModel` 都设置该属性。
5. 改 `EntityAbilityBehaviorPlanner` 的候选集构造：检测到模型带 `scripted_enemy_case` 时，把该 case 的 entity/capability/behavior IDs 加入候选查询，避免短 prompt 导致候选缺失。
6. 让 `ScriptedEnemyChatModel` 的 `EncounterSpecPlanner` 分支从 `scene-spawn-manifest.json` 选 spawn group：优先 `room_01_guard`，否则选第一个合法 group；manifest 为空直接失败。
7. 新增 `tools/run_enemy_mainchain_pie.py`，串起生成、stage、tsc、PIE、日志切片验证。
8. 扩展 `validate_autoue_runtime_log.py` 和对应测试，保证攻击相位链是硬 gate。

## Implementation Details

- `core/llm_factory.py`
  - 增加 `ScriptedEnemyChatModel(case)`。
  - `create_llm()` 支持 `provider == "scripted_enemy"`。
  - `ScriptedSmokeChatModel` 增加 `use_mcp_fixture=True`，新 enemy model 同样设置，供 UE API 节点用 fixture evidence。

- `config/llm-profiles.example.json`
  - 增加 `scripted_enemy_zombie`、`scripted_enemy_archer`、`scripted_enemy_kamikaze`、`scripted_enemy_shield`。

- `custom_nodes`
  - `entity_ability_behavior_planner`：若模型带 `scripted_enemy_case`，candidate set 查询追加该 case 的 entity/capability/behavior IDs。
  - `ue_api_mcp_feasibility_searcher`：`_use_fixture()` 改为检查模型属性 `use_mcp_fixture`，不再硬编码类名 `ScriptedSmokeChatModel`。

- scene-spawn-manifest 来源
  - 主链路测试用临时 config 打开 `scene_spawn_manifest.allow_fixture=true` + `fixture_path=tests/fixtures/scene-spawn-manifest.valid.json`。
  - 真机导出用 `scene_spawn_manifest.enabled=true` + `unreal_editor/project/map` 走 `tools/unreal/export_scene_spawn_manifest.py`。
  - `EncounterSpecPlanner` 不伪造坐标；manifest 缺失、为空或无合法 group 时直接失败。

- Runner 行为
  - `--case all` 顺序跑四个 case。
  - `--pie` 缺失时只做 repo/mainchain/stage/tsc 级验证。
  - `--pie` 存在时，PIE 失败即失败，不降级冒充完成。
  - Blueprint uasset、`GlobalDefaultGameMode`、地图内 `AUTOUE_ENEMY_SPAWN_POINT` 缺失时提前失败并打印缺失项，不自动伪造。

- `typescript_codegen.json` 的 `required_runtime_modules` 包含对应敌人 runtime 模块。

## 完成口径

- 只生成 TypeScript：未完成。
- 只 stage 到 AIDev / tsc 通过：未完成，只能称为 repo/stage 级通过。
- `run_autoue_pie_validation.py` 只返回 enemy_count > 0：仍未完成敌人战斗验证。
- 只有同时满足“目标敌人生成、攻击相位日志链出现、case-specific 日志出现、无旧日志假阳性”，才算主链路敌人 PIE 跑通。
- 如果 live PIE 环境缺 spawn point、adapter、GameMode、UE Editor 或超时，结果必须标为“repo 级通过，PIE 待验/被环境阻塞”，不能宣称完成。

## Assumptions

- `scripted_smoke` 继续保留 freeze trap 冒烟用途，不改成敌人。
- `config/local.json` 仍指向当前真实 AIDev：`D:\UE5.7.4\AIDev`。
- PIE 真跑依赖地图里已有可用 enemy spawn point 和现有 TypeScript Blueprint adapter；缺失时 runner 必须失败并报告，不自动伪造。
- scripted enemy profiles 是主链路确定性 smoke；真实自然语言 LLM prompt 的稳定选择质量另行验收，不混入本次完成口径。
