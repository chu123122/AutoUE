# 敌人行为填充玩法设计方案

## 结论

当前敌人系统已经有实体参数和部分运行时骨架，但还没有形成完整玩法。敌人的移动、血量、感知距离、攻击距离、攻击伤害、冷却、ActorClass、ProjectileClass 等参数可以从实体/能力参数传入；真正缺的是：

1. 不同敌人行为模式的决策组织。
2. 不同攻击类型的真实执行。
3. 攻击生命周期。
4. 攻击和受击的可见表现。

也就是说，后续重点不是继续堆参数，而是把“攻击类型 + 命中检测 + 表现反馈 + 状态阶段”补完整。

---

## 一、敌人玩法应拆成四层

### 1. 敌人实体 Entity

实体负责描述敌人的基础数据和默认参数。

典型字段：

- `hp`
- `move_speed`
- `detect_range`
- `attack_range`
- `attack_damage`
- `attack_cooldown`
- `actor_class_path`
- `projectile_class_path`
- `hitbox_radius`
- `keep_distance`
- `explode_radius`

示例敌人：

- 僵尸：追击近战。
- 弓箭手：保持距离远程攻击。
- 自爆怪：高速接近后爆炸。
- 盾兵：正面格挡 + 近战反击。
- 重型怪：低速高伤害。
- 精英怪：多段攻击或混合攻击。

---

### 2. 行为模式 Behavior Pattern

行为模式负责描述敌人“怎么决策”，不是攻击本身。

典型行为模式：

| 行为模式 | 移动策略 | 攻击策略 | 特点 |
|---|---|---|---|
| `fast_chase_and_melee` | 追击玩家 | 近战碰撞 | 快速贴脸攻击 |
| `heavy_chase_and_melee` | 慢速追击 | 高伤害近战 | 慢但危险 |
| `keep_distance_and_projectile` | 保持距离 | 发射投射物 | 风筝玩家 |
| `chase_and_self_destruct` | 快速追击 | 自爆范围伤害 | 接近后爆炸 |
| `shield_chase_counter` | 追击玩家 | 格挡 + 近战 | 正面防御 |

一个行为模式通常组合这些能力：

```text
感知玩家
移动策略
攻击策略
受伤逻辑
死亡逻辑
房间完成逻辑
```

---

### 3. 攻击类型 Attack Type

攻击类型负责描述“如何命中玩家”。这是当前最需要填充的部分。

| 攻击类型 | 命中方式 | 需要实现 |
|---|---|---|
| `melee_hitbox` | 近战碰撞体 / sphere overlap / capsule sweep | 前方范围检测、命中窗口、伤害 |
| `projectile_spawn` | 生成投射物 | 方向、速度、命中回调、生命周期 |
| `self_destruct` | 半径爆炸 | 前摇、范围 overlap、伤害、自毁 |
| `area_burst` | 范围爆发 | 地面提示圈、延迟伤害 |
| `charge_attack` | 冲锋碰撞 | 冲刺移动 + sweep 命中 |
| `directional_block` | 防御判定 | 受击方向、格挡角度、减伤/免伤 |
| `combo_melee` | 多段近战 | 多 hit window、连击节奏 |

当前已有的 `EnemyCombat.resolveMeleeHit`、`EnemyCombat.spawnProjectile`、`EnemyCombat.selfDestruct` 只是雏形，需要扩展为真实攻击生命周期。

---

### 4. 表现 Presentation

即使把攻击改成真实碰撞，如果没有表现层，玩家仍然会感觉敌人在“隐形攻击”。

需要补一个表现运行时：

```text
EnemyPresentationRuntime
```

它负责：

| 事件 | 表现 |
|---|---|
| 感知玩家 | 警示标记、材质变色 |
| 攻击前摇 | 红色闪烁、攻击范围提示 |
| 攻击生效 | hitbox 短暂显示、挥砍轨迹 |
| 投射物发射 | muzzle flash、projectile mesh |
| 命中 | 受击闪白、飘字、击退 |
| 自爆 | 爆炸球体、屏幕震动 |
| 死亡 | dissolve、destroy、掉落 |

---

## 二、推荐运行时结构

不要把所有表现和命中逻辑都塞进 `enemy_combat.ts`。推荐拆成：

```text
EnemyBrain
  决定当前敌人要做什么

EnemyMovement
  执行追击、保持距离、逃跑、冲锋

EnemyCombat
  管理攻击生命周期和伤害结算

EnemyPresentationRuntime
  管理前摇、命中、受伤、死亡等表现

WorldAdapter
  提供 UE 查询、碰撞、spawn、damage、visibility 等底层接口
```

攻击执行统一流程：

```text
1. EnemyBrain 判断可以攻击
2. EnemyCombat 进入 Telegraphing
3. EnemyPresentationRuntime 播放前摇表现
4. 等待 windup
5. 进入 Active 命中窗口
6. WorldAdapter 执行 overlap / trace / projectile hit
7. 命中后 applyDamage
8. EnemyPresentationRuntime 播放命中反馈
9. 进入 Recovering
10. 进入 Cooldown
```

## 三、三个基础敌人玩法案例

### 1. 僵尸：追击近战

实体参数：

```text
hp = 100
move_speed = 260
detect_range = 900
attack_range = 160
attack_damage = 10
attack_cooldown = 1.2
windup = 0.35
recover = 0.45
```

行为组合：

```text
detect_player_by_distance
chase_target
melee_hitbox
receive_damage
emit_death_event
complete_when_all_dead
```

运行效果：

```text
看到玩家 -> 追击 -> 进入攻击距离 -> 红色前摇 -> 前方碰撞检测 -> 命中扣血 -> 后摇 -> 冷却
```

---

### 2. 弓箭手：保持距离远程攻击

实体参数：

```text
hp = 70
move_speed = 220
detect_range = 1200
keep_distance = 500
attack_cooldown = 1.8
projectile_speed = 900
projectile_class_path = /Game/...
windup = 0.5
```

行为组合：

```text
detect_player_by_distance
keep_distance
projectile_spawn
receive_damage
emit_death_event
complete_when_all_dead
```

运行效果：

```text
看到玩家 -> 保持距离 -> 抬手预警 -> 发射投射物 -> projectile 命中玩家才扣血
```

---

### 3. 自爆怪：追击自爆

实体参数：

```text
hp = 40
move_speed = 480
detect_range = 1000
explode_radius = 220
attack_damage = 35
windup = 0.8
```

行为组合：

```text
detect_player_by_distance
chase_target
self_destruct
receive_damage
emit_death_event
complete_when_all_dead
```

运行效果：

```text
看到玩家 -> 快速靠近 -> 进入爆炸范围 -> 闪烁前摇 -> sphere overlap -> 范围伤害 -> 自毁
```

## 四、需要补的关键模块

### 1. WorldAdapter 命中查询

需要新增或补齐：

```text
resolveMelee(source, params)
overlapActors(center, radius, params)
resolveExplosion(source, params)
resolveProjectileHit(projectile, params)
```

用途：

- 玩家攻击用 `resolveMelee()` 找敌人。
- 敌人近战用 `resolveMelee()` 找玩家。
- 自爆和范围攻击用 `overlapActors()`。
- 投射物用真实命中回调或 overlap/trace。

---

### 2. EnemyCombat 攻击生命周期

当前攻击过于瞬时。需要变为状态机：

```text
Idle
Telegraphing
Active
Recovering
Cooldown
```

每个攻击类型都应该有：

```text
windup_seconds
active_seconds
recover_seconds
cooldown_seconds
hitbox_radius
attack_range
attack_damage
```

---

### 3. EnemyPresentationRuntime

负责把逻辑事件转为可见反馈。

最小版本可以先做：

```text
telegraph(enemy, attackType, params)
showHitbox(enemy, params)
impact(target, params)
death(enemy, params)
```

表现可以先用简单占位实现：

- 动态材质变红。
- 临时球体/盒体显示攻击范围。
- 命中时目标闪白。
- 自爆时生成放大球体或 Niagara。

---

## 五、最小落地顺序

### 第一阶段：近战怪可玩

目标：僵尸追击玩家，前摇后真实碰撞命中。

需要完成：

1. `world_adapter.resolveMelee()`。
2. `EnemyCombat.resolveMeleeHit()` 改成前摇 + active hit window。
3. `EnemyPresentationRuntime.telegraph()`。
4. PIE 日志输出：

```text
EnemyAttackTelegraph
EnemyAttackActive
EnemyAttackResolved hit=1/0
EnemyDamaged
```

---

### 第二阶段：远程怪可玩

目标：弓箭手保持距离并发射投射物。

需要完成：

1. `EnemyCombat.spawnProjectile()` 补方向、速度、生命周期。
2. `WorldAdapter.spawnProjectile()` 支持默认 projectile class 或 fixture。
3. 投射物命中玩家才扣血。
4. 发射表现。

---

### 第三阶段：自爆怪可玩

目标：自爆怪接近玩家后前摇爆炸。

需要完成：

1. `EnemyCombat.selfDestruct()` 改为前摇后 `overlapActors()`。
2. 爆炸范围表现。
3. 爆炸后死亡事件。

---

### 第四阶段：盾兵 / 精英怪扩展

目标：组合已有攻击和防御能力。

需要完成：

1. `directional_block` 按受击方向判断。
2. `combo_melee` 多段攻击。
3. `charge_attack` 冲锋攻击。
4. 行为模式支持多攻击策略选择。

---

## 六、验收标准

不能只看 TS 编译通过。至少需要：

1. 生成物包含对应敌人 runtime 模板。
2. PIE 中能刷出敌人。
3. 敌人能感知玩家。
4. 敌人移动策略生效。
5. 攻击有前摇表现。
6. 攻击只在真实命中时造成伤害。
7. 命中和死亡有可见反馈。
8. 日志能证明完整链路：

```text
EnemySpawned
EnemyDetectedPlayer
EnemyMove
EnemyAttackTelegraph
EnemyAttackActive
EnemyAttackResolved
EnemyDamaged
EnemyDeath
EncounterComplete
```

---

## 七、关键判断

移动和基础参数已经在实体/能力里定义，但这只解决了“敌人有什么数值”。

真正的玩法实现还需要：

```text
攻击类型的真实执行
攻击生命周期
真实碰撞检测
可见攻击表现
行为模式中的策略选择
```

因此当前最优先的不是继续扩实体参数，而是先做三种基础攻击闭环：

```text
melee_hitbox
projectile_spawn
self_destruct
```

这三种跑通后，敌人系统才算从“有参数和骨架”进入“有实际玩法”。
