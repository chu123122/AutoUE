SCHEMA: TypeScriptImplementationSlotProjector

Deterministic Python node: convert PuerTS runtime mappings into TypeScript/PuerTS implementation slots. This node must not ask an LLM to make implementation decisions.

Required JSON shape:
{
  "typescript_sources": [
    {"path": "TypeScript/content/generated/ExampleAbility.ts", "role": "runtime_owner", "notes": "runtime_owner from mapping"}
  ],
  "implementation_slots": [
    {
      "entity_id": "entity id from mapping",
      "behavior_id": "behavior id from mapping",
      "flow_id": "flow id from mapping",
      "runtime_mapping_path": "flow/05-puerts-runtime-mapping.json",
      "target_ts_file": "TypeScript/content/generated/ExampleAbility.ts",
      "reason": "mapped from PuerTSRuntimeMappingCompiler.runtime_owner"
    }
  ],
  "missing_slots": []
}

Rules:
- Output JSON only.
- Every mapping must produce exactly one behavior-level implementation slot whose target_ts_file equals mapping.runtime_owner.
- Copy entity_id, behavior_id, flow_id, runtime_mapping_path, and runtime_owner directly from PuerTSRuntimeMappingCompiler data.
- missing_slots is only for mappings missing required deterministic fields; normal workflow/runtime closure requires it to be empty.
- Support files such as AIDev runtime orchestrator, CharacterAdapter, GameModeAdapter, camera helper, spawn point registry, enemy spawn manager, and encounter manager are generated by TypeScriptRuntimeTemplatePlanner, not as extra analyzer slots.
- Do not create slots that do not come from runtime mapping.
